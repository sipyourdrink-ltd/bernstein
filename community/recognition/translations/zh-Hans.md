朋友们，你们好。

我最近想了一下，我觉得，如果大约每两周一次，Bernstein 在 LinkedIn 上的主页亲自点名每一位想被提到的贡献者，并在同一条帖子里感谢他们，这应该不会要了我的命。

一条帖子。不是每人一条。我们的关注者不需要连续十条帖子，我也不需要一份专门写这些帖子的第二职业。但在这一条帖子里，我想尽量对每个人说清楚你到底做了什么，这样如果有潜在雇主读到，他们能明白你在一个真实项目里构建了什么，你也不会不好意思转发它。

顺便说一句，我们其实已经开始做这件事了。#5524 里有 LinkedIn 页面，还有不少人说"行，写上我的名字"，#6229 是第一次整合致谢的尝试。所以这不是什么新东西。这只是我想不再每次都手动拼凑这件事。你们中已经在 #5524 里说过愿意的人不用再说一次，我已经记下你们了。

## 这事儿是怎么回事

从你这边来看，整个流程是：

1. 你在过去三个月里在 Bernstein 做了有意义的工作。
2. 你关注了项目主页：https://www.linkedin.com/company/bernstein-run/
3. 主页会不时发布一条整合帖子，点名 opt in 的人以及他们做了什么。
4. 如果你愿意，就转发它，最好 tag 上 Bernstein。
5. 项目获得了原本得不到的曝光。你获得了一份公开的、专业的记录，而且不是你自己写自己的。

就这样。没有第六步。

如果你现在正在找工作，还有一个选项：我可以从我的个人主页（https://www.linkedin.com/in/alex-chernysh/）给你写一份 LinkedIn 推荐信，而不是发帖。这不麻烦。但我想把这个取舍说清楚：推荐信留在我的主页上，帮的是你；而转发那条共同的帖子，同时帮到你和项目。而且说实话，几乎没人会往下翻到 Recommendations 那一栏。所以推荐信主要留给你正在积极找工作的时候用，其他时候就用转发。如果两个都想要，说一声就行。

关于这一切的价值。如果你真的做了这些工作，就别藏着。把 Bernstein 写进你的简历、你的作品集，任何合适的地方。我自己会这么做，你们中有些人已经这么做了，我觉得这是个不错的信号：在一个严肃的开源项目里，一个你能逐行讲清楚的、被合并的贡献，比简历上一句"会 Python"更有价值。这是我的观点，不是研究结论。它也不是任何承诺：这是一个志愿项目，没有人在招聘，我更愿意现在把这话说明白，而不是让谁以后从里面读出别的意思。

## 如何说"我愿意"

发一封邮件。地址和主题要完全一样：

> **To:** forte@bernstein.run
> **Subject:** `BRNSTN-PR-LNKD`

在正文里，写几行脚本能读懂的内容：

```
GITHUB=your-github-login
OPT_IN=YES
RECOMMENDATION=NO
```

如果你想要 LinkedIn 推荐信，代替帖子，或者和帖子一起，就把 RECOMMENDATION=YES 设上。如果有什么我该知道的事，加一行 NOTE=（比如你想在发出前先看一下措辞；已经有几个人这么要求了，没问题）。以后想 opt out，同样的地址，同样的主题，OPT_IN=NO。

请不要改动 subject line。解析脚本要的就是完全一致的那个字符串。收到的邮件量之大，这不是个人喜好问题；主题不同的邮件会落进普通队列，我不能保证我一定会看到它。

## 这个软门槛，以及它为什么是软的

为了在不用我逐个手动看每个 PR 的情况下决定谁能进某一条帖子，有一个机械化的过滤条件：过去 30 天内已合并的 pull request 中大约新增 1,000 行，生成文件不计入。这不是 KPI。不是质量指标。也不是对任何人的评判。这只是让一个脚本能每隔几周不需要人工介入就拼出一批名单的省事办法。

而且它也不是一道死板的围墙。这里有人做安全工作、做 review、写文档、做 benchmark、搞发布相关的杂活，还有调试，这些哪怕只有四十行的 diff 也可能极具价值。如果你确实做了有意义的工作，只是因为某些原因没到一千行，写信到同一个地址、同一个主题说明情况就行。我们不是怪物，总能想出办法。通常的答案是，我们给你找下一个任务，你在下一次贡献里就跨过那个不太走运的一千行门槛了。

定期名单里的名字按字母顺序排列。不是按 PR 数量，也不是按我更喜欢谁。字母顺序。

## GitHub Discussions 和 LinkedIn 主页不是竞争关系

它们干的是不同的事。对于快讯（一次发布、一项变更、一条社区更新），LinkedIn 主页是更快的渠道。GitHub Discussions 才是你真正参与这个项目的地方：你能看到上下文，能争论，能提议，能找到答案，而且它会留下记录，让下一个人能找到。如果你既想要资讯也想要深度，那就两个都关注。决策仍然发生在 issue 和 pull request 里，这一点没有变。

## 我为什么要做这件事

你们中很多人还很年轻。有些人已经不那么年轻了。但对刚起步的人来说，一个真正的开源项目是相当难得的机会，可以去尝试不只是写代码，还有 review、架构、测试、文档、安全、发布、协调，甚至一点公开写作，还能做出真正有后果的决定。如果我在读大学的时候就能参与这样的东西，我的人生大概会走得挺不一样。所以我想尽我所能地支持刚起步的建造者。

我的方法很简单：把里程碑切成一个人能扛得住的小块，给某人一个真实的任务，把决定权留给能由他们做决定的地方，不要在第一次犯错后就把任务收回，让人随着经历的增多去承担更多责任。

对你们中正在学什么 CS 相关内容的人，或者刚刚起步的人：我看见你们了。我和你们在一起。你们做得很好。

再说一个观点，明确标注这只是个观点。会写代码正在变成一项基本技能，就像会打字一样。会思考，能看到取舍，能做出一个自己能站得住脚辩护的决定，这仍然稀有，而在 AI 时代，我猜这只会变得更稀有、更有价值，不会变得更不值钱。这里就是练这个的地方。

## 目前项目是怎么运作的

到今年年底之前，我仍然是唯一的 maintainer。这是故意的。这不代表 maintainer 什么都要决定。所有权是我的；但我不认为我该亲自去挑架构里的每一个逗号。如果你是来提 PR 的，我希望你去思考，而不是去猜 maintainer 想要什么。

等我有精力的时候——现在我确实被别的事情压得有点喘不过气——我想试着让工作更有形一点，用虚拟的"部门"，就像一家普通公司那样。全部自愿，没有任何义务，也不搞为了搞而搞的官僚流程。一开始我只看到两个：R&D，它已经活在 issue 和 pull request 里，几乎不需要我操心；还有 PR / outreach，我大概会盯得稍紧一点，因为没有结构的沟通，比我知道的任何东西都更快地变成"我们该找个时间做那个"。

以后，如果活跃的人足够多，一些角色可能会跟上：一个负责开发的 director，一个负责运营的，一个负责安全的，一个负责 QA 和文档的。我不会提前创造这些头衔。人数决定结构，不是反过来。没人需要一个六个人的公司架构。

## 钱的事，因为总有人会问

当有人问 Bernstein 上是否有付费机会时，我有时会发出一声紧张的轻笑。Bernstein 不赚钱。它花的是我的钱。我甚至都不算自己的时间；我只是看着钱从银行账户流出去，在一个物价相当高的国家，而我目前正处于两份工作之间，情况大概还会再给我这个项目多留一两周。所以我在做的不是无偿工作。这是亏本经营。我喜欢这份工作。基本上，这就是我们大家都在这里的原因。

对用户免费不等于对 maintainer 免费。这背后的基础设施每月大约要花几千美元，而这笔账单不管有没有人在 LinkedIn 上发帖都照样会来。

关于许可证，说得精确一点，因为我自己有一次在脑子里就把这个想错了：Bernstein 用的是 Apache-2.0。Apache-2.0 允许商业用途；它并不要求任何人保持非商业。Bernstein 过去是、现在是，就我而言以后也会一直是一个自由的开源项目——这是一个立场和意图，不是许可证的条款。

一个自由项目照样可以有赞助商、广告、合作展示位、相关的集成。如果你认识某个 AI 实验室或这个领域里的某家公司，觉得这真的合理，帮我引荐一下。我会试着在接下来几周内整理出一份像样的合作方案，然后我们再看能拿它做点什么。在那之前还有 GitHub Sponsors，它存在，但规模很小。

一条硬规矩。任何付费集成都绝不能买到一次 merge。如果某家公司想为某项具体的集成工作付钱，这项工作照样走正常的技术流程，maintainer 和社区保留说不的权利，一个技术决定不会因为出现了预算就改变。如果哪次付费工作真的被批准了，收益会用于托管、运营成本和维护这个项目的人。这不是一份薪酬政策；没有百分比；这只是说明钱会去哪儿。

再说一件人情味的事。如果 Bernstein 周围真的出现了一个实打实的付费机会，那些已经投入过工作、我已经认识的人，显然会是我最先考虑的人之一。这不是承诺，不是计划，也不是"现在先免费干，以后再被雇用"。这只是那种普通的逻辑：如果我已经喜欢一个人思考和做事的方式，我会在想到陌生人之前先想到他。

## 谁在看着，为什么这很重要

我们当然不能公开整套分析流程，但从各种迹象来看，读者不止我们这些人。大型 IT 公司和 AI 实验室的人相当有规律地出现在网站上，对文档提出相当具体的问题。竞争对手，我们不妨假设，也没在睡觉。

顺便说一句：根据我们的被动分析数据，去掉明显的机器人噪音之后，Bernstein 现在在全球至少大约 3,000 台机器上稳定运行。我觉得这个数字相当值得一提。Bernstein 默认不发送任何产品遥测数据，这个数字也不是从任何遥测数据来的；它是一个被动信号，关于方法我只能说这么多。

所以局面已经很有意思了。我们在打造一个人们真正在用的免费产品，它吸引了工程师、AI 实验室和大公司的关注，而任何用户都可以拿走源代码并拥有它。我的观点，明确说这是个观点：当你能免费得到一个严肃的工具并拥有代码时，就很难解释为什么还有人愿意每月花几万美元去买一个类似的东西。

我想让这个项目有一种"大"的感觉。不是为了让我们能跟别人说自己很牛，而是为了让在这里工作的每个人都明白，他们做的事可能远远超出一次 pull request 的意义。我心里的标杆大致是 Ansible、Kubernetes、Terraform。不是说"Bernstein 是下一个 Kubernetes"。而是说：如果 Bernstein 有一天真的成为它这个类别里的参考实现，我不想回过头来觉得我们当时做得太急。我们应该把它做好。

## 几点老实话

我不能保证节奏。"大约每两周一次"是一个目标，不是服务级别承诺。完全有可能第一条帖子两周后就到期，然后一个月过去了，然后发现我们想先自动化另外三件事，于是原本几周就能做完的事悄悄拖到了年底。我们会尽力。我不会向你承诺一件我自己都不确定能不能兑现的事。

大约在 11 月中旬，如果一切顺利、精力允许的话，我想开一个简短的 Zoom 通话。就是见个面，聊聊你们每个人想往哪个方向走。不强制参加，目前也没有确定日期。

我们尊重这个项目里的人说着不同的语言，所以原文保留英文，下面的评论里会跟几个翻译版本。这只是一个想让你们感觉稍微舒服一点的小小尝试，仅此而已。

在我这边，基本上就是我和这只猫。在你们那边，是你们所有人。

Sharing is caring。我尽量把能给的都还给你们，为你们的工作，也只是为了你们在这里。相信我，我真的很喜欢你们所有人。这也是让我每天早上起床、坐到电脑前的原因之一，之后我才发现十五个小时已经过去了。让我们看看，这一切最后会变成什么样子。
