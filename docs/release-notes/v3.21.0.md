# v3.21.0

Two hundred and forty-four changes since v3.20.0; read the two advisories
first.

An agent could write its own identity record and be believed; an empty
`<task>.approved` file passed for an operator's decision
(GHSA-xw82-w5hr-hrm2, high, reported privately). Workflow commands ran
repository text in untrusted workspaces, a claim took its role from the
request, and a receipt verified against whatever key it carried
(GHSA-4r8r-jx5c-w954, high, reported by @Trenyx). Fixed in #6404; every
version through 3.20.0 is affected. Upgrade first.

The rest is ordinary governance work: records that verify, a benchmark that
cannot be flattered, runs that stop for the reasons they state.

## The receipts we are not proud of

Row five is the class we hunt hardest: a guard that fails open and
leaves a record saying it passed. A cooldown that never fired, a rollback that
returned `True` over nothing, a signer with a public key. Each now has a test
that fails on the old code.

## On upgrade

- Old identity records are ignored; re-spawn agents.
- A bare `.approved` or `.rejected` file rejects the task; decide again, with
  CLI, task server and orchestrator on one audit key.
- A `docker` sandbox no longer sees the host tree.
- Receipt verification fails without a pinned key; `--allow-unpinned-key`
  keeps the old result.
- A non-manager token with an empty task list reaches no task.
- Policy limits make no network call without `api_url`.
- On Windows, `bernstein cleanup` removes managed worktrees.
- The skill catalog cache moved to `$XDG_CACHE_HOME/bernstein/`.
