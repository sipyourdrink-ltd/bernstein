# v4.0.2

A patch release on top of v4.0.1 covering server access gates, default loopback `Host` header checks, adapter and journal fixes, and conformance tests. Review the loopback `Host` header change below before upgrading if a reverse proxy, tunnel, or container alias fronts a loopback-bound server.

## Loopback Host header guard and GUI bearer token

Loopback-bound servers (`127.0.0.1`, `localhost`, or `::1`) enable the `Host` header guard by default across `bernstein gui serve` (without `--tunnel`), `bernstein serve`, and `bernstein run`, rejecting non-loopback `Host` headers (anything outside `localhost`, `localhost.localdomain`, `127.0.0.0/8`, or `::1`) with HTTP 403 or WebSocket close code 1008 (#8181). Set `BERNSTEIN_ALLOWED_HOSTS` to a comma-separated list of permitted hostnames when a reverse proxy, tunnel, or container alias forwards a non-loopback `Host` header. On loopback binds (`--no-open` and `--dev` included, without `--tunnel`), `bernstein gui serve` persists the auto-minted GUI API bearer token to `.sdd/runtime/auth.token` (`0600`) when `.sdd/` exists and reuses it across launches instead of rotating on every start (non-loopback and `--tunnel` binds never auto-mint); `bernstein run` surfaces `.sdd/runtime/auth.token` in bootstrap output while minting a fresh per-run token when `BERNSTEIN_AUTH_TOKEN` is unset.

## Server gates and file permissions

WebSocket handshakes to `/ws` and `/api/v1/ws` traverse the same authentication, IP allowlist, and request-limit middleware as HTTP `GET`, returning `401`, `403`, or `429` on rejection and requiring `Authorization: Bearer` on the handshake (#8150). `POST /a2a/v1/oauth/token` (and its `/api/v1` alias) shares the login attempt budget and failed-credential backoff, and `POST /a2a/v1` applies backoff to invalid API keys and bearer tokens without counting successful calls (#8151). The SSE reconnect limiter counts `/api/v1/events`, `/api/v1/events/cost`, and `/api/v1/events/thread` against the same per-client budget as canonical routes (#8152). Dashboard task log streams read new lines on a worker thread, and ticket validation reuses the current schema validator including date checks (#7643).

`write_atomic_bytes` stages files at `0o600`, validates wider explicit modes before applying them, and rejects group/world-writable or special-bit modes (`0o022` or outside `0o777`); `ScheduleStore` and `ScheduleSupervisor` write specs and receipts at `0o600` instead of `0o666`, `a2a_cmd._reissue_expired_card` clamps preserved modes to `0o644`, and volunteer preflight enforces anchored HTTPS `github.com/<owner>/<repo>[.git]` URLs via `ensure_public_http_url` and `StrictHTTPRedirectHandler` (#8160).

## Runtime, adapters, CLI, and tests

`GeminiAdapter` sets `default_model = "gemini-3-flash"` so zero-config and `bernstein demo --real --adapter gemini` runs avoid `ModelNotConfiguredError` (#8154). Gateway-only retry resolution skips the Claude tier ladder on non-Claude adapters (`OPENAI_API_BASE` or non-Claude `role_model_policy`), leaving bare `sonnet`/`opus`/`haiku` labels unset while keeping explicit pins, `metadata.pinned_model`, provider-prefixed models, and the Claude ladder unchanged (#6605). Task journal replay preserves claim timestamps and claimants on pending stops unless explicitly set to `null` (#7952). `bernstein demo` and `bernstein demo --flask-todo` seeds declare `quality_gates: {enabled: false}` so `bernstein trace export` computes `policy.bundle_hash` out of the box (#8159). `bernstein wiki build` keeps Unicode Python filenames and groups top-level `src/` modules together (#7902). The auditor conformance suite covers all 21 registered questions with authority (#5059) and data/endpoint (#5061) vectors (`asked 21/21, answered 4/21`) (#5054), and `tests/unit/test_orchestrator.py` pins per-test thread and RSS teardown budgets (#6042).

## Upgrading

```bash
pipx upgrade bernstein     # or: uv tool upgrade bernstein
```

Configure `BERNSTEIN_ALLOWED_HOSTS` before upgrading if a reverse proxy, tunnel, or container alias fronts a loopback server. No configuration file migration is required.
