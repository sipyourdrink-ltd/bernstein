# v3.23.0

One hundred and five changes since v3.22.0. Several fix work that looked finished until somebody checked the evidence.

Artifact completion now enforces the criteria in `artifact_spec`, as well as completion signals. A failed criterion cannot produce a signed success receipt ([#6638](https://github.com/sipyourdrink-ltd/bernstein/issues/6638)). Plan loading preserves all eleven native completion-signal types; malformed declarations fail before dispatch ([#6646](https://github.com/sipyourdrink-ltd/bernstein/issues/6646)). Server launch, supervisor restart and watchdog recovery retain the selected absolute seed path and refuse an unavailable or invalid policy ([#6643](https://github.com/sipyourdrink-ltd/bernstein/issues/6643)).

## Work without an orchestrator

Administrative runs group manually claimed tasks under an audited container. They start no planner or worker. Membership, tenant boundaries and aggregate completion are checked against the installation audit chain; a mismatch refuses certification. The receipt hash alone does not authenticate the aggregate ([#6722](https://github.com/sipyourdrink-ltd/bernstein/pull/6722)).

Role sessions can subscribe to task-creation events over SSE. Delivery is bounded and in memory: it does not wake an agent or replay missed events ([#6721](https://github.com/sipyourdrink-ltd/bernstein/pull/6721)). Bare MCP and REST tasks can enter the signed claim/completion lifecycle without duplicate backlog rows ([#6725](https://github.com/sipyourdrink-ltd/bernstein/pull/6725)).

Bandit and Checkov adapters record deterministic findings and invocation provenance. Checkov isolates home configuration and refuses configurations that load external checks or modules. This is part of the scanner work, not the entire scanner catalog ([#2958](https://github.com/sipyourdrink-ltd/bernstein/issues/2958)).

## On upgrade

- Bandit needs its `sarif` extra. A scanner without it is refused with the installation remedy.
- Evolution backups now use a proposal-specific storage key. An older `UPG-NNNN` backup is refused for rollback: restore its manifest's files manually, or move the directory aside after checking the tree. Old history rows cannot establish ownership of a new proposal ([#6186](https://github.com/sipyourdrink-ltd/bernstein/issues/6186)).
- Kimi remains pinned to `kimi-cli==1.51.0`; the archived CLI's final version exits without doing the task. Its successor needs a separate adapter ([#6264](https://github.com/sipyourdrink-ltd/bernstein/issues/6264)).
- Incident eval cases in managed projects now belong in the run-state incident-case directory, outside the project's source tree. Move or remove an old generated source directory ([#6529](https://github.com/sipyourdrink-ltd/bernstein/pull/6529)).
- Resume `trace follow` JSON output into JSONL, not a previous one-shot JSON array. Use a fresh file when changing formats ([#6397](https://github.com/sipyourdrink-ltd/bernstein/issues/6397)).

## Evidence and policy

Run archives can anchor their manifest digest in a verified HMAC audit log. File hashes and attestation are reported separately: a rewritten manifest is `unattested`, even when its recomputed hashes agree ([#6258](https://github.com/sipyourdrink-ltd/bernstein/issues/6258)). Installed packages now carry the standalone audit-receipt verifier, so both receipt-verification commands work outside a source checkout ([#6534](https://github.com/sipyourdrink-ltd/bernstein/pull/6534)).

An explicitly wired attestation interlock records `toolcall.effect` after connector return, hashing the actual response bytes. A missing effect remains unobserved; the gateway does not enable this interlock by default ([#6270](https://github.com/sipyourdrink-ltd/bernstein/issues/6270)). Offline hardware evidence verifies pinned PIV chains and retained FIDO2 enrollment/assertions. Touch proves presence, not informed intent; this does not raise the TRACE trust level. It does not enroll credentials, contact hardware, check revocation or authorize actions automatically ([#6724](https://github.com/sipyourdrink-ltd/bernstein/pull/6724)).

`leakage-v1` checks seeded secrets in emitted benchmark, pack, archive, log and PR-projection bytes. Receipts retain bytes and nonces for rescanning; unexercised journal, receipt, telemetry and environment surfaces remain explicit omissions ([#5450](https://github.com/sipyourdrink-ltd/bernstein/issues/5450)). PII exemptions now cover the benign value rather than its entire line, so a placeholder cannot hide an adjacent credential ([#6321](https://github.com/sipyourdrink-ltd/bernstein/issues/6321)).

DLP seed settings reach the parser, and persisted verdicts include effective policy in their cache keys ([#6615](https://github.com/sipyourdrink-ltd/bernstein/issues/6615)). The optional `test_expansion` gate follows static imports from changed tests to changed production modules; it does not measure runtime coverage or resolve dynamic imports ([#6151](https://github.com/sipyourdrink-ltd/bernstein/issues/6151)). `govern audit --only duplication` inspects the installed package; absent subjects are `not_measurable`, and the checks remain opt-in ([#5105](https://github.com/sipyourdrink-ltd/bernstein/issues/5105)).

## Runtime and operators

Manager, planner and backlog task bodies share one builder, preserving completion signals and allowed context metadata. Stored membership hints do not implicitly select an administrative run ([#6300](https://github.com/sipyourdrink-ltd/bernstein/issues/6300)). Transitive file affinity cannot combine tasks with conflicting model, adapter or preferred-agent hints ([#6626](https://github.com/sipyourdrink-ltd/bernstein/pull/6626)). Tier-aware backend hints and a Prefect REST bridge add dispatch options ([#6573](https://github.com/sipyourdrink-ltd/bernstein/pull/6573), [#6570](https://github.com/sipyourdrink-ltd/bernstein/pull/6570)).

Cost-anomaly checks observe resolved spawn models and retry lineage. A stop pauses spawning until operator resume; disabling the policy keeps it inert ([#5942](https://github.com/sipyourdrink-ltd/bernstein/issues/5942)). Compaction retries consult verified failure evidence and priced budget hops. Task-scoped tokens cannot alter ladder authority; evidence producers and tick-loop retries remain follow-ups ([#4855](https://github.com/sipyourdrink-ltd/bernstein/issues/4855)).

`bernstein sandbox leaks` lists unresolved sessions whose owning tasks are recorded finished. Unknown or active tasks are explained as exclusions; unreadable or replay-skipped evidence refuses the listing. It does not implement age-based cleanup ([#5112](https://github.com/sipyourdrink-ltd/bernstein/issues/5112)). File locks with no live holder are released each tick ([#6536](https://github.com/sipyourdrink-ltd/bernstein/pull/6536)). `post_merge` hooks fire after successful merge-back; hook failure cannot undo the merge ([#5962](https://github.com/sipyourdrink-ltd/bernstein/issues/5962)). Notification registry conflicts identify both modules and preserve the original registration; the wider registry work remains partial ([#5104](https://github.com/sipyourdrink-ltd/bernstein/issues/5104)).

`trace follow` gains resume, file export and live following; reused task IDs stay live while a related run occurrence is active ([#5114](https://github.com/sipyourdrink-ltd/bernstein/issues/5114)). `bernstein insights` is reachable and emits valid JSON or literal text, but still computes no analytics ([#5880](https://github.com/sipyourdrink-ltd/bernstein/issues/5880)).

Cluster nodes survive central restart and heartbeat limits are isolated. Remote work uses a shared remote and merge-preview verification of posted artifacts; remote report delivery is not universally solved. Adapter backoff releases a claim, resumed sessions receive their preserved worktree, and terminal failures are not reopened by the completion chain ([#6610](https://github.com/sipyourdrink-ltd/bernstein/pull/6610), [#6568](https://github.com/sipyourdrink-ltd/bernstein/pull/6568), [#6612](https://github.com/sipyourdrink-ltd/bernstein/pull/6612), [#6530](https://github.com/sipyourdrink-ltd/bernstein/pull/6530), [#6532](https://github.com/sipyourdrink-ltd/bernstein/pull/6532), [#6543](https://github.com/sipyourdrink-ltd/bernstein/pull/6543)).

## Adapter repairs

Auggie uses print mode and the credentials it reads. Kilo uses supported `run` flags; per-task MCP settings are reported as undelivered. Letta starts without conflicting conversation flags ([#6588](https://github.com/sipyourdrink-ltd/bernstein/issues/6588)). Mistral refuses unsupported temperature requests before spawn. Pi disables operator extensions ([#5965](https://github.com/sipyourdrink-ltd/bernstein/issues/5965)). Charm and Continue contracts are filed under their registered adapter names.

## CI, tests, docs and dependencies

Queue classification includes the whole stacked batch, so a docs-only entry cannot hide preceding Python changes ([#5901](https://github.com/sipyourdrink-ltd/bernstein/issues/5901)). Mutation timeout probes use per-test repositories rather than mutating modules other test processes import. This does not establish a green mutation nightly ([#6471](https://github.com/sipyourdrink-ltd/bernstein/issues/6471)). Policy, journal and audit-pack tests cover additional mutation boundaries; stall primitive invariants do not imply completed lifecycle wiring.

Copr publishing has its own deployment environment. Workflow cache writes are restricted, TruffleHog action/scanner versions agree, and the dependency updates include MCP 1.30.0, the compatible OpenTelemetry cohort, certifi, graphql-core, Vite/Tailwind and TanStack Query. README translations and curated agent context now describe the reviewed runtime scope.
