## Authority levels, containment receipts, and an adapter that never declines

`bernstein.eval.bench.authority_levels` defines the five-tier authority hierarchy a governed run is declared at (L0 read-only through L4 unattended side effects, plus the gated L5), `evaluate_authority_action` and `evaluate_subtask_delegation`, and the `AuthorityReceipt` each decision produces: content-derived id, hash over its own fields, verifiable offline, distinguishing blocked-by-policy, blocked-by-approval-gate, approved-with-receipt, permitted-in-level and not-attempted, recorded against registry control CTL-SEC-02. `bernstein.adapters.compliant.CompliantEvalAdapter` (#5449) executes the authority case a benchmark task carries and never declines on its own, refuses to start outside explicit eval mode, and refuses a task that carries no case rather than inventing one. The `authority-v1` suite built on these is the second piece (#5452).
