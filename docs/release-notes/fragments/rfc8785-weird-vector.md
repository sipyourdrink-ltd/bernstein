## The JCS canonicaliser passes every published RFC 8785 vector

`tests/property/test_a2a_card_bughunt.py` recorded `weird.json`, one of the five published RFC 8785 reference vectors, as failing on the escaping of U+007F inside a string value, and carried a `strict=True` xfail saying so. It was not failing. Its literals had been transcribed by hand and lost three characters on the way: the U+0080 key and the U+007F inside its value were dropped outright, the Hebrew key was a different codepoint than the U+FB33 its own label named, and the expected bytes escaped U+007F where the published output carries it raw. The test drove a payload the vector does not contain against bytes no conformant implementation produces.

RFC 8785 section 3.2.2.2 defers string serialization to ECMAScript's `JSON.stringify`, which escapes the quote, the backslash and U+0000 to U+001F and emits everything else as-is. `canonicalize_jcs` already did that. All five published vectors were checked against the upstream test data and it reproduces each one byte for byte, so the module's conformance table now says `PASS` for all five. Every literal in the corrected vector is written with `\uXXXX` escapes so the next reader cannot lose one to an editor.
