## A repository URL the parser refuses is a refusal, not a traceback

`repo_url_problem` is the gate deciding whether a repository URL from a claimed volunteer task may be handed to `git`. It read the scheme with `urllib.parse.urlparse`, which raises `ValueError` on a bracketed-IPv6 netloc carrying userinfo (`http://[::1]@evil.com/x.git`) and on a stray or unclosed bracket. The call was unguarded, so a task carrying such a URL left `run_claimed_task` with a traceback instead of the `TaskRefusal` the volunteer protocol records, and the refusal receipt a verifier reads was never written. Such a URL never reached `git` before either, since the exception aborted the whole call: this converts a crash into a recorded refusal rather than closing an execution path. `claim.repo_slug` reads the same untrusted URL through the same unguarded call; a URL that will not parse names no GitHub issue, so it returns `None`, which is what that function already returns for a URL with no host (#5515).
