## `BERNSTEIN_MODEL_REGISTRY_ENFORCEMENT` now gates every spawn

The fail-closed model-registry check was implemented as four per-path wrappers (`route_decision`, `cascade_router`, `escalation_ladder`, `model_fallback`) that no routing code ever called, so setting the flag changed nothing and no refusal was ever written to the audit chain. The check now runs where the model choice is final, immediately before an agent process or provider batch job starts: the fresh-spawn path (after the router, role policy and any operator pin are applied), a router failover to a different provider or model, crash-resume spawns, and provider batch submission. With the flag set, a model with no live admission is refused, the refusal is appended to the audit chain with the dispatch path that asked, and no agent is started; a missing or unreadable audit chain also refuses. With the flag unset, behaviour is unchanged and the audit chain is not opened. The registry provider is the adapter's declared model vendor (else the routed provider or adapter name) and the task class is the task role. The three unused per-path wrappers are removed.

## Governance coverage table lists unwired controls as unwired

`docs/governance/coverage.yaml` marked the scoped command allowlist as `covered` and the prompt-injection scanner and parallel admission as `partial`, but none of the three is called by any run path. They are now `none` (linked to the open reachability audit), the plugin trust row says it is a `bernstein plugins` report rather than a load gate, and their cited tests are dropped because those tests only exercise the code in isolation.
