## govern discover: existence means re-observed recently

`govern discover` runs repeatedly against the same targets, but the observation envelope from #5082 had no persistence: an entity unplugged six months ago looked identical to one seen five minutes ago. A new `ObservationStore` persists envelopes under `.sdd/govern/inventory/observations/`, one file per entity id, with three lifecycle operations. `upsert` refreshes `observed_at` under the stable entity id instead of appending a second entry, so two overlapping passes over an unchanged fixture converge to byte-identical state. `sweep` demotes entities not re-observed within a configurable TTL to a `tombstoned` state -- nothing is ever hard-deleted -- journals every transition, and returns the count moved. A tombstoned entity observed again is restored and that restoration is journaled too, so "when did we stop seeing X" and "did X come back" are answerable from `journal.jsonl` alone. Tombstones live as a `state` field on the same entity record rather than a separate store, so the inventory selector (#5116) can query live and tombstoned from one place (#5083).
