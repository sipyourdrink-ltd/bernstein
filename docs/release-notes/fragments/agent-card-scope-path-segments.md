## Agent-card scope matches path segments, not string prefixes

`AgentIdentityCard.in_scope` decided membership with `path.startswith(prefix)`. That answers a different question, and gets it wrong in both directions that matter: `"/src/api-internal/keys.pem"` starts with `"/src/api"` but is a different directory, and `"/src/api/../../etc/passwd"` starts with it while resolving outside the tree entirely.

`in_scope` has no production call site today - it is reached only from tests - so nothing shipped was relying on the broken answer. It is a scope primitive on an identity card and will be wired up, which is the reason to make it correct before that happens rather than after.

Membership is now decided on whole path segments, with either separator recognised so a scope written on one host is read the same way on another, and a `..` component refused rather than compared. A leading separator is not significant: an absolute spelling and its relative one collapse to the same scope, which is the contract a caller gets. A scope entry that names no segment (`"/"`, `""`) contains nothing rather than everything - a zero-length prefix matched every path, so one stray entry silently unrestricted the card - and a scope made entirely of such entries admits nothing, which is the fail-closed direction `core/security/guardrail_pipeline.py` already chose for the same defect on the modified-file manifest (#5488).
