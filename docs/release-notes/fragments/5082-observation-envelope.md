## govern discover: one observation envelope per entity, with an errors map that names each gap

`govern discover` observes whole entities with many attributes at once, but the inventory it builds on models one surface as a single flat value — there was nowhere to record that three of an entity's five attributes collected fine and two did not, or why. A new `ObservationEnvelope` carries the entity id, entity class, collected payload, observed-at and an `errors` map keyed by sub-probe naming the reason each missing field is absent, so "not collected, here's why" never reads as "collected, value is empty". The entity id is derived from the entity's normalised key the same way `identity_join` derives graph ids, so the same entity observed under two hostnames is one entity; and when two envelopes do collide on one id, the ledger disambiguates with a per-envelope short-hash key instead of silently shadowing the second entry the way `Inventory.get_surface` does today (#5082).
