A remote worker's completion that passes the janitor now lands on the run branch. The alive-exit pass already materialised the posted artifact as `agent/remote-<task>-v<n>` and graded the merged tree; with no session to reap, nothing merged that branch and the task stayed `done` with its work stranded. The verdict pass now checks the branch out and registers it under a synthetic session named after it, runs the same verification gates a local agent's work meets (quality gates, rule enforcement, cross-model review, formal verification), then the approval gate, then merges through the spawner's merge path, so the merge queue, default-branch guard, blast-radius ceiling, signed file scope, quality gates, landed provenance and push all apply. It then closes the task, seals its evidence, records the merge in the run journal and removes the branch. A checkout that fails, a merge that returns no result, or a non-conflict merge failure takes the bounded reopen budget and keeps the branch; a conflict creates a resolver task; an approval hold keeps the worktree and the branch, and in PR mode the pull request is opened from them.
