## Delegation verification detects changes to a sealed final receipt chain

Run close atomically seals the final delegation digest, hop count and manifest
configuration with the install audit key. Every delegation verifier checks that
seal and the declared head/count: tail deletion, substitution and post-close
growth fail, even if a keyless writer recomputes the manifest checksum. Missing
declarations are incomplete (`valid=false`, exit `3`), including pre-upgrade runs
and interrupted finalization. Existing unsigned head declarations fail seal
verification; they are not silently upgraded from the remaining ledger (#5352).

Open and legacy runs retain their intact, authority-checked delegated ceilings
in the agent registry, marked by `incomplete_runs`; saved version-1 registry
snapshots remain verifiable. Access reviews exclude incomplete or mismatched
chains from verified sources. Incomplete chains never report a passing verdict.

This does not detect replay of an earlier authentic snapshot, prove that every
runtime action was recorded, or protect against a writer holding the audit key.
Deleting a declaration yields incomplete, never a completeness claim. There is
no automatic backfill: the remaining receipts cannot establish a historical tail.
