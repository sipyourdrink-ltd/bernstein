## CAS GC refuses to sweep on a partial mark

`bernstein gc cas` is a mark-and-sweep collector: it walks the durable roots for referenced digests, then deletes unreferenced blobs older than the retention window. A root it could not read contributed nothing, so a blob whose only reference lived there was indistinguishable from an unreferenced one and was deleted, with nothing in the result telling the operator a root had been skipped.

Both ways a root goes unread now reach the caller. A scanner raising outright was the loud one; the failure that actually happens is a per-file `OSError` swallowed inside a scanner, which a permissions problem, a transient I/O error or a network-filesystem hiccup on a single spine file produces, and which used to leave the mark looking complete. The sweep deletes nothing when either has occurred: the counts still describe what a complete mark would have considered, the way they do for a dry run, and `bernstein gc cas` exits non-zero saying it refused rather than reporting a deletion it did not perform.

Two supporting changes. The lineage scanner no longer raises `AttributeError` on a spine line that is not an object or whose `content_hash` is not a string, which used to take an entire root out of the mark. And the prune receipt's `root_set_hash` carries a digest over the root set the sweep was decided against, instead of the `null` it has held since the field was added; the unreadable roots are hashed in too, so a partial answer and a complete one cannot collide. Receipts are now version 2, and one is only written for a sweep whose mark phase read every root (#5508).
