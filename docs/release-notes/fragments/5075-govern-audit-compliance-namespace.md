## The compliance policy library reports through `govern audit`

The 23 checks in `core/security/compliance_library.py` were reachable only from the config seeder, and `bernstein compliance check` evaluated a separate snapshot built from command-line flags, so the two surfaces could describe one install differently. Every check is now registered under a stable `CMP-nnn` id and reported by `bernstein govern audit`, and both surfaces read the install through one function — the policy snapshot and the audit findings are two projections of one read. A check that only tests whether a key is present in a configuration file now reports `declared` instead of a pass, and its summary names that gap; the five checks that read the filesystem report `measured` and carry the digest of every locator they probed, recording a probed absence rather than empty evidence. `--profile <framework>` marks which ids a framework requires and asserts nothing about the result: there is no score, no grade, and every count names its denominator.
