## Agent identity records are authenticated with a key outside the workdir

Spawned agents run as the orchestrator's OS user from a worktree under `.sdd/worktrees/`, so they can read every file under `.sdd/` and write new ones there. The agent identity store treated any well-formed record under `.sdd/auth/agent_identities/` as an identity, and the secret that signs agent tokens was stored beside the records. A record that the orchestrator never minted could therefore carry a role and permissions nobody granted, and it was picked up again after a restart.

Every identity record now carries a MAC under a key derived from the install audit key, which already lives outside the workdir (`BERNSTEIN_AUDIT_KEY_PATH`, else the XDG state directory, mode `0600`). Every reader ignores, and logs, a record whose MAC is missing or wrong or whose id does not match its file name. Role, permissions and task scope come only from authenticated records; a token whose claims differ from its record, extra scopes included, does not authenticate. The default token-signing secret is derived from the same key, so nothing under `.sdd/` signs a token; `BERNSTEIN_AUTH_JWT_SECRET` still overrides it. No new setup is needed.

Upgrade note: records written before this change carry no MAC and are ignored, so agents spawned before the upgrade must be re-spawned. The old `.sdd/auth/agent_identity_jwt_secret` is no longer read and is removed when the store starts. Records can no longer be repaired by hand; revoke and re-spawn instead. Processes that mint and verify identities on different hosts must share the audit key.

Limits: the install key is a file owned by the same OS user, so an agent that is not confined by a sandbox can still read it from the home directory. A process that can write `.sdd/` can also restore an earlier authentic copy of a record for the remaining lifetime of its token.

Related hardening: the auto-approve classifier now denies shell redirects and file-writing tools that target `.sdd/` or `.bernstein/` through an absolute, `./`-prefixed or quoted path, and any such target containing a `..` segment; previously only the relative form was denied. The read-only, builder and reviewer permission profiles deny `**/.sdd/auth/**`.
