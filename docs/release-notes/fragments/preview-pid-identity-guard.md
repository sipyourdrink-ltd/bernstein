## Fail-closed PID identity guard for preview teardown

`PreviewManager` now records process start identity (`PreviewState.process_start_time` via a lazy `psutil` import and, on Linux, monotonic `/proc/<pid>/stat` field-22 `starttime` ticks in `PreviewState.process_start_ticks`) when spawning a host dev-server process and fails closed before delivering `SIGTERM` during `stop`, `stop_all`, or `reap_expired`. Minimal installs without `psutil` import the CLI and preview modules cleanly and fail closed with `psutil_unavailable` instead of signaling blindly; invalid, boolean, or init PIDs (`<= 1`), our own PID, any PID sharing our process group (or with `pgid <= 1`), legacy state without start identity, unreadable process metadata, and stale reused PIDs with a mismatched start identity receive no signal while the skipped PID and reason are logged, recorded in the `preview.stop` audit entry, reported by `bernstein preview stop` / `stop --all`, and the persisted preview state is still cleaned up.
