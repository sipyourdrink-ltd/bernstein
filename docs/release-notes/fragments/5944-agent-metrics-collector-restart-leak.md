## Agent metrics no longer leak into a second Orchestrator built in the same process

`Orchestrator.__init__` already reset task metrics for a fresh instance, but the
process-wide metrics singleton kept whatever agent metrics an earlier `Orchestrator`
in the same process had recorded (test isolation, embedding one host in another).
A retrospective generated by the new instance could then mix in the old one's
agents, skew `get_total_cost()`'s summary total, and crash formatting the summary
if one of those agents never had its role resolved to a plain string. Production
only ever builds one `Orchestrator` per process, so this did not affect it. Agent
metrics are now cleared on construction the same way task metrics already were
(#5944).
