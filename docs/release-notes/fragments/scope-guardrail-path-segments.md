## Scope guardrail matches path segments, not string prefixes

`ScopeGuardrail` decided whether a modified file was inside the agent's declared scope with `str.startswith`, which accepted two paths that are not in scope: a sibling directory sharing the prefix (`src_evil/foo.py` against a scope of `src`) and a traversal that starts inside and points outside (`src/../etc/passwd` against a scope of `src/`). An agent that chooses its own modified-file manifest could spell either. Membership is now decided on whole path segments, and a manifest entry that is absolute or carries a `..` component is refused by the same `validate_relative_path` barrier the rest of the codebase uses, on both path separators. A scope entry that is not itself a safe relative path now admits nothing rather than matching loosely.
