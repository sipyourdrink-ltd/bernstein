# v3.22.0

Seventy-five changes since v3.21.0. Upgrade for the first one.

A run that stopped on purpose could be restarted by its own recovery
watchdog. On 3.21.0, a run with one planned docs task restarted the
orchestrator five times, re-queued retries that an earlier process had already
made, and ended with 20 of 21 tasks failed and the requested change never
written. A run that reaches quiescence now stays stopped, and a restarted
orchestrator does not duplicate retries (#6474). Any run on 3.21.0 that
stops on quiescence is exposed.

The rest is smaller: audit verification that checks what was signed, gates
that block what they report, and commands that stop when they cannot work.

## The question you get asked

| The question | Before | Now |
|---|---|---|
| Does a run that stopped on purpose stay stopped? | The watchdog never read the deliberate-stop marker, the stand-down check looked at the wrong journal row, the owner record named the wrong row so recovery was refused, and a task whose description mentioned lint was finished by the fast path without an agent. | The watchdog reads the marker, stand-down accepts `run_completed` anywhere in the owner's journal, the owner record is published right after `run_started`, only a task's title selects the fast path, and a restart marks existing retries as handled (#6474). No adapter configured exits `1` before anything starts (#6427). Janitor retries keep the original completion signals, owned files and dependencies (#6460). |
| Does the audit check read what was signed? | `verify_incremental` trusted a segment whose bytes matched its unsigned tile, so an edit with a rewritten tile passed; after a seal and one append it reported a broken chain; a cut-back or deleted sealed segment read as clean. | Trust comes from the newest signed checkpoint, and only records appended after the pin are walked (#6435). A pinned segment that is gone, shorter than its pin, or changed is reported, and an `ack-tear` acknowledgement is honoured (#6443). Tiles are written with LF endings on every platform (#6435). |
| Do the gates block what they report? | `pii_scan` passed an SSN or card number because the rules were graded medium; `dlp_scan` skipped a whole line for one benign token; the SBOM gate read every osv-scanner finding as `unknown`; a foreign attestation could declare `operator` trust and be believed. | `pii_scan` blocks on each finding's `block_merge` (#6321). `dlp_scan` exempts a finding only when the benign token overlaps the flagged value (#6430). osv-scanner severities are read, so `block_on_critical` answers 422 (#6434). A foreign attestation's trust class is capped at `third_party`; above that it is `malformed` (#6431). |
| Does the benchmark measure what it claims? | A drop in the gate-evasion catch rate could merge unnoticed. | CI compares against a content-addressed baseline and rejects a lower catch rate, a lost class or an unverified measurement (#6461). `goal-drift-v1` scores trajectories against explicit contracts without model calls (#5566), and scenario summaries report expected value and a Brier score (#6395). |
| Does the command do what it printed? | `cli: antigravity` resolved to the Gemini adapter and passed flags the Antigravity CLI rejects; bare `volunteer` signed consent over invented digests; the ACTIVITY pane printed a log line again on every poll; `--quiet` reset the root logger. | `antigravity` resolves to the `agy` adapter (#6411). `volunteer` records nothing and exits non-zero until a task source exists (#6428). The pane prints a line once (#6323). `--verbose` and `--quiet` touch only the `bernstein` logger (#6192). New: `govern audit` with `--list`, `--only` and `--skip` (#5803), `govern lane` with `bootstrap`, `list` and `show` (#5743) and `govern lane retire` (#6475), `trace export --format ocsf` (#6400), bounded declared probes (#6302). |

## On upgrade

- `bernstein govern audit` no longer runs the verifier-key staleness check; use `govern audit-keys` (#5803).
- `--quiet` silences only the `bernstein` logger; pass third-party libraries their own level (#6192).
- `pii_scan` and `dlp_scan` can block merges that passed before (#6321, #6430).
- A foreign attestation claiming more than `third_party` trust is `malformed` (#6431).
- Exported trust records carry a `kid` derived from the key's RFC 7638 thumbprint (#6412).
- `cli: antigravity` needs the `agy` binary; the Gemini adapter resolves only `gemini` (#6411).
- Bare `bernstein volunteer` exits non-zero and writes no consent receipt (#6428).
- `bernstein -g` with no adapter exits `1` instead of reporting success (#6427).

Records: the read-set refusal receipt hashes `changed_paths` in sorted order,
and receipts minted unsorted still verify (#6312); a salvage merge is
journalled as `task_merged` with its `merge_commit` (#5387); the file signer
advertises a JWK and `key_kind: hsm` says it is unimplemented (#5704); tests
pin the audit tail digest against a line truncated mid-write (#6181).

Runtime: a worktree excludes every configured `copy_files` name from the
agent's index (#5980); the QA role prompt finds the repository's own lint and
test commands instead of assuming `ruff` (#6432); `run_guardrails` no longer
builds a decision graph it never reads (#6322); the heartbeat reap verifies a
pid's command line through `psutil`, so on Windows a recycled pid is no longer
signalled unverified (#6508).

CI and tests: merge groups run the whole unit-test list after a green group
broke `main`, and the impacted-test slice stays on pull requests (#6468, #5809);
`auto_merge_enabled` no longer re-triggers the policy workflow (#6449); the
unreachable-controls allowlist drops `record_lane_retired` once a command
calls it (#6467); the watchdog cycle tests stub only bootstrap's clock (#6489);
fixture-tree gate output stays out of a real-tree failure report (#6410); root
logging state is restored after every test (#6324); sandbox budget exhaustion
has boundary tests (#6448); a lineage test imports `resource` only where it
runs (#6496).

Docs: `SECURITY.md` names 3.21.x and a test derives the line from the version
(#6166); the docs home page states a checked adapter floor (#6167); the FINOS
crosswalk uses the published identifiers (#6436); the review roster gains
triagers, area reviewers and role terms (#6314); the adapter last-green table
was regenerated (#6398, #6420, #6459, #6476, #6493); a contributor opt-in
follows a renamed account (#6472).

Dependencies: docs pins (#6414), werkzeug 3.1.9 (#6421), fsspec (#6422),
multidict (#6423), source-map-js in the web lockfile (#6453), handlebars in
the VS Code extension lockfile (#6470), and the npm group (#6309).
