# v3.19.2

Two hundred and twenty-nine changes since v3.19.1, and one of them is why this
page arrives ahead of the usual cadence.

`bernstein audit verify` could print its green panel while the grant sweep it
had just run was holding a critical finding. The chain verified, the command
reported success, and the finding left with exit code zero. That is
GHSA-594x-5h3g-wj34, severity low, reported by @Silentpartnercoding and fixed
in `06850966d` (#5784). Everything up to and including 3.19.1 is affected. If
you gate a pipeline on `audit verify`, upgrade before reading the rest.

The rest is what a governance layer does between security fixes: guards that
had been answering the wrong question, and receipts that say more about their
own limits than about our good intentions.

## The question you get asked

| The question | Before | Now |
|---|---|---|
| Does a green verdict mean it was verified? | `audit verify` weighed chain failures only, so a critical sweep finding sat under a green panel (GHSA-594x-5h3g-wj34). | A finding is a refusal, printed with its own text, and every reconcile asserts the revoked grant set against what the provider still serves (#5122). A gate result carries a structured scope — how far the claim reaches, its confidence, the canonical bytes receipts use (#5397, #5395); the merge-admission receipt carries the coverage sets behind it (#5398), and `bernstein verify coverage` reads them back (#5400). A completion claiming a verification must name where it was recorded (#5001). Verification executes the change rather than only reading it: boundary inputs derived from the changed signatures, no model and no randomness (#3377). Whole-tree guards run on every pull request, not only on `main` (#5428), and an adjudication record names the identity that produced it and how independent it was (#5473). |
| Which of your guards were guarding? | Several matched on the wrong thing and answered "clean". | The scope guardrail matches path segments, not string prefixes. The secret-leak guardrail knows the token formats vendors issue today. Injection detectors fold obfuscated spellings and read the payload shapes they are handed. The residency guard returns a verdict for a URL it cannot parse; a repository URL the parser refuses is a refusal, not a traceback; a DSSE failure names its cause instead of vanishing into a broad `except`. `JWTManager` signed SHA-256 whatever its header claimed, and under `HOME=/` the redactor rewrote every string it touched. The uncalled-security-control guard recognises same-module callers (#5336), and the caller-less-module guards report both drift directions in one run (#5552). |
| Who was this agent allowed to be? | Identity minted per credential format; authority decided once, at spawn. | Agent identity has one type and one namespace (#5097), and the principals in play are projected from the audit chain (#4969). Every spawned agent leaves a delegation receipt, and a run that cannot record one does not spawn (#5047). `identity review` derives a signed access review from those chains (#4974); `identity export-verifier` writes a standalone verifier for the exports (#5115). The permission boundary speaks AuthZEN 1.0 (#5032), every approval resolution names the principal behind it (#5035), and `bernstein.yaml` declares which executors a repository may spawn on, with the gate failing closed (#4907). |
| Can I trust the time, and the bytes? | Our word against yours. | `seal publish` anchors a run's sealed head to an outside RFC 3161 authority (#4205). Run-receipt binding bytes sign as RFC 8785 (#5274), evidence packs digest under the same rule rather than a local convention (#5504), and a real signed record now exercises its UTF-16 key ordering (#5551). The run receipt binds the audit range it embeds (#5269) and states what share of the run it covers (#4968). `sandbox attest` mints a signed isolation attestation for the host (#3278). The seal records whether execution had actually stopped (#5272), the ordinary `task_merged` row names the commit it produced (#5271), and the govern plan names its own decision record (#4982). A scorecard is projected from the sealed journal (#5402), bound to it as a signed artefact (#5403), and reachable as `runs scorecard` (#5404). Conformance vectors cover the bundle-only and endpoint cases (#5061). |
| Where did this value come from? | Whichever configuration file you happened to open. | `config explain` names the layer and the file behind every value (#5110). Policy composes in a fixed order and states which layer wrote what (#5117); a derived classification fact names the rule that derived it (#5121). A change receipt keeps the prior value, so the restore plan is read off the record (#5109). A finding is suppressed through a chain-anchored decision with a reason and an expiry (#5078). The compliance library reports through one command (#5075), the docs separate a declared posture from a verified control (#5056), and playbook remedies collect into one plan (#5079). |
| Is the inventory still true? | A list, correct on the day someone wrote it. | It records when it last saw each surface (#5083). Discovery writes one observation envelope per entity, with an errors map naming each gap (#5082), and what a pass collects, how, and for how long it stays valid is a declared record rather than a dispatch branch (#5081). Which governed targets lack the agent is a query (#5118). Reconciliation lanes are data and bootstrap is create-if-absent (#5120); stale inventory and report reads are refused rather than served (#5130); capabilities with more than one implementation are counted continuously (#5105). Every run records the skill and plugin set it actually loaded (#4986). `lineage plan` renders a run's whole task graph from its journal (#4958), `trace follow` reports every trace referencing one entity (#5114), and `lineage sensitivity` reports effective sensitivity against an operator-controlled source map (#5042). |
| What happens when a run dies badly? | Sometimes nothing, sometimes the wrong thing. | Crash recovery reads the uncommitted index instead of replaying every write-ahead log; trigger state and fleet contexts are written crash-safely, and seven more atomic writers followed; the content-addressed collector refuses to sweep on a partial mark. `RunActor` refuses a terminal-status transition instead of silently rewinding (#5088). A clean exit that left uncommitted work is not recorded as "no changes needed", an agent that exited zero is not failed for what it printed, and a task that finished mid-tick is not reopened as an orphan. A failed task no longer ends the run before its retry exists, a successful retry unblocks its dependents, and runs that succeeded only after retrying are reported (#5106). `tuning.agent` and `tuning.task` reach the code that judges and kills, and a raised `max_agent_runtime_s` is honoured as a deadline floor (#5379). Batch work gets a per-item ledger and a daily cap derived from it (#5126); one broken skill source no longer takes every other skill with it (#5108); `worktrees gc` is a dry run unless you ask it to delete (#5112); a routine's cooldown resets only on a run that found something (#5113). |

## The receipts we are not proud of

The second row is the class we hunt hardest. A guard that fails open is worse
than no guard, because it leaves behind a record saying the check passed. Each
of those shipped with a test that fails on the old code. Two components also
described themselves inaccurately: `PluginTrust` claimed cryptographic and
provenance verification it never performed, and a quality gate's docstring
promised guarantees the code did not make. Three A2A findings were re-recorded
against what shipped rather than against what the report assumed.

## For the engineers

Adapters: OpenCode's declared event channel matches what the CLI emits (#3676)
and a bare model id is qualified or refused before spawn (#5350); the run-level
adapter survives a registry-key lookup and the provider fallback uses that key
(#5348); the host-isolation declaration reaches the run-level adapter (#5341);
a multi-key adapter class disambiguates its reverse lookup (#5497); the
capability contract table is back in step with the strategy matrix (#5627).
Observability: webhook event types are declared in a catalogue and an unknown
one is ignored rather than guessed (#5132), plugins can announce ingest adapter
declarations (#4963), and every outbound model call emits a check record at the
boundary (#5477). Evolution: `ChangeContract` is a typed value on
`UpgradeProposal` (#5405) with a replay service behind it (#5406), and the
constraint layer is one manifest with immutable hash-locks (#5440). Evaluation:
a tool-surface risk suite with forced approval gating (#5454), plus bench
rotation, a private holdout and contamination checks (#5459). Quality:
fast-path lint stays inside the worktree (#5390), the dead-code gate no longer
crashes (#5572), a roadmap wave that emits nothing says why (#5573), mutant
timeouts come from the module budget and are not scored as kills (#5621),
salvage staging skips local editor settings (#5620), the confidence ledger
upgrades its own table on connect (#5493), and an unpriced model name warns
once and reads `unpriced` rather than `$0.00` (#5337). Terminal and CLI:
dashboard polls stop once shutdown begins (#5616), the published render no
longer depends on how loaded the machine drawing it is, `--port` reaches the
agents and not only the server, a leading dot in a filename is part of the
name, and a codex agent inside a Bernstein worktree can commit again. CI:
sharded pull-request lanes compare against a pinned base commit, the test job
fetches the pull request's head and establishes `origin/HEAD`, the queue's
ALLGREEN grouping tradeoff and bisection runbook are written down (#5506), the
merge-gate page stops restating the queue configuration, `docs/requirements.txt`
transitive pins were re-resolved (#5623), and the reviews a pull request still
needs are read from the rules on the default branch rather than the branch under
review (#5785). `ADOPTERS.md` says who runs this, on what, and since when
(#5027), and the French README has an owner (#5275), alongside newly adopted
Finnish, Hebrew, Italian, Korean, Polish and Portuguese translations.

## On upgrade

- `pip install --upgrade bernstein`. No configuration or schema changes.
- If a pipeline gates on `bernstein audit verify`, expect it to start failing
  wherever the grant sweep has a finding. That is the fix, not a regression.
- `bernstein worktrees gc` no longer deletes by default; pass the delete flag
  where you relied on the old behaviour.
- An `admission:` block in `bernstein.yaml` is optional, but once present the
  spawn gate fails closed against it.
