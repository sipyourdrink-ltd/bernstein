# v3.14.159

The minor landed on 14, so the version is π to three digits; if this line
ever needs a patch it will append digits — 3.14.1592 — the way TeX does.
That is the only whimsical thing in here.

This is the release where the surface stopped pretending. A first-use report
(discussion #3514) described ninety minutes of setup that ended in nothing:
an error message recommending a flag that does not exist, a run that produced
no plan and said nothing, and a command list too large to hold in one head.
Most of what shipped since v3.13.0 answers some part of that, directly or by
removing the class of defect behind it: the command surface is being folded
into group owners, most with deprecation windows, the reference docs are now
gated against the registered CLI so they cannot drift apart again, the plan
loader now raises named errors for the malformed fields it used to swallow,
and the README states plainly
that this is a beta maintained by one person. Around that, five new
integration surfaces, a run receipt that verifies offline, and the usual
floor-raising: two mypy backlogs cleared, coverage ratcheted three times.

## Behaviour changes (read before upgrading)

- **Plan loading rejects what it used to swallow (#3534, #3539).** An
  out-of-range enum, a scalar where `files` expects a list, a `priority` that
  is not an integer, an explicit `null` — all of these previously loaded as
  defaults or passed validation outright, which is how a run could start,
  produce no plan, and say nothing. They now raise `PlanLoadError` with the
  field named, and `validate_plan` enforces the same types and ranges the
  JSON schema declares. A plan file that has been silently wrong now fails
  loudly at load; that is the point. One surface still masks the failure:
  the standalone `bernstein dry-run --plan` converts a load error into an
  empty result and exits 0 — #3550 tracks propagating it.

- **Command folds and renames, with windows — and five removals without
  (#3501–#3505, #3411, #3371, #3370, #3472).** `quickstart`, `init-wizard`,
  `validate` and `routine` fold into their domain owners; benchmark
  subcommands fold into `eval`; impact analysis consolidates under
  `bernstein impact`; `changelog` and `run-changelog` swap names;
  `bernstein listen` moves to an optional voice extra. Those folds keep
  aliases for the documented window (#3419 fixes the one window that was
  misstated), so scripts get a deprecation notice before they get a break.
  Five names do not get a window: `postmortem`, `incident` and
  `commit-stats` moved under `report` (#3370) and their top-level aliases
  were then removed (#3472), so the old invocations now fail with "No such
  command" — the replacements are `bernstein report postmortem`,
  `bernstein report incident` and `bernstein report commits` (note the
  rename: `commit-stats` is now `report commits`). The `consensus` and
  `issue-to-pr` groups are removed outright in the same PR. This is the
  start of the surface reduction, not the end of it.

- **`evolution_enabled: false` disables the evolution loop (#3397).** It
  previously did not, which is the kind of sentence a config option should
  never need written about it.

- **The verification absence cases below downgrade, not pass.** An attestation public key
  that cannot be parsed is a containment failure (#3494); a missing identity
  signal downgrades the verdict as documented instead of passing it (#3429);
  a symlinked gate-receipt store is refused and the resolved path is read
  (#3414); `telemetry verify-span` exit codes now match `trace
  verify-projection` for these downgrade cases (#3407). One absence case
  still diverges: removed audit evidence passes `trace verify-projection`
  (exit 0) but fails `telemetry verify-span` (exit 1) — #3551 tracks
  unifying it. One tolerance did not change this release: both verifiers
  still load the event journal leniently, so a malformed journal row is
  skipped rather than failing the verdict — #3549 tracks making the verify
  paths load strictly.

## The first-use path

- **The no-adapter fatal names a flag that exists (#3530).** It recommended
  `--adapter`, which belongs to an internal subprocess; it now names `--cli`,
  and a test resolves every flag and command in that message against the
  live CLI so the text cannot drift back.
- **The documented fresh-install path was walked and its stumbles fixed
  (#3352),** the demo produces real completion evidence instead of mock
  theater (#3432, #3436), and the front page shows a recorded real run that
  ships its own proof (#3438, #3441, #3442).
- **The reference docs are gated, not groomed.** The registered-vs-documented
  CLI gate (#3511, #3462) fails CI when a command or flag exists in only one
  of the two places, and the flag tables were reconciled against the
  registry in one sweep (#3536). Twenty-three commands documenting flags the
  parser rejects is the defect class this closes.
- **The README says beta (#3543).** Solo-maintained, version numbers count
  releases rather than maturity, pin what you depend on. The dashboard also
  stops depending on an external font host to boot (#3546), which mattered
  exactly in the air-gapped installs the README advertises.
- **Issue templates run (#3471).** The commands they told reporters to run
  were broken; there is now also a verification-failure form, because
  "verify said no" deserves structured intake.

## New surfaces

- **Muse Code adapter (#3542).** Wraps the vendor's headless one-shot mode
  (`muse exec`), env passthrough for its API key, single-model lineup pinned
  rather than remapped. Verified against vendor docs dated in the adapter's
  docstring, like every other adapter.
- **Kimchi CLI adapter with ACP ingress conformance (#3509)** and a
  **generic Python-invoked agent-runtime adapter (#3510)** for runtimes that
  are libraries rather than binaries.
- **Playwright browser driver (#3508, #3507)** with pinned build identity,
  profile isolation, and driver selection at the activity boundary behind a
  conformance kit.
- **Agent Plugins v1.0.0 manifests (#3541).** The repo root now carries
  `plugin.json` and `mcp.json` conforming to the open spec, generated and
  version-stamped, validated in CI against vendored schemas — standards-
  following hosts can discover the bundle without special-casing; nothing
  fetched at load time, so the air-gap story holds.
- **A read-only datasource query driver (#3386)** that binds results to
  their schema snapshot.

## Verifiability

- **A signed run receipt that verifies fully offline (#3387)**, and
  **`bernstein audit diagnose` (#3388)**, which names the first faulty step
  from the signed per-step journal instead of leaving the operator to bisect.
- **Tool-call identity is bound per dispatch (#3420)** on top of run-anchored
  agent identity (#3367), with a native tool-call evidence provider bound to
  the audit chain (#3359) and a provider-neutral attestation interlock
  (#3353).
- **Evaluation grows teeth:** a deterministic pass^k reliability floor
  (#3384) with an `eval --reliability K` alias (#3406), clean-run
  attestation proving ground truth was never fetched (#3415), a COSE /
  in-toto / RFC 6962 projection for trajectory receipts (#3480), and a
  multi-tier verifier ladder with signed per-tier receipts on the pre-merge
  gate (#3409).
- **Declared context files reach the worker and the attachment set is
  recorded (#3408)**, and admission decides parallel execution from the code
  graph rather than task descriptions (#3478).

## Correctness

- **Cluster registration works (#3524):** `RegisterNode` built its
  `NodeInfo` with keyword mismatches and failed; caught by an outside
  contributor, finished together.
- **Artifact-mode tasks are routed off the git-only paths (#3416)** —
  worktree allocation and batch APIs no longer assume every task ends in a
  commit.
- **Two memo-keying defects (#3486, #3487)** where cache entries keyed on a
  shim instead of the source they summarize, **the Hermes adapter drives its
  one-shot flag instead of a bare prompt (#3490)**, and the TUI resolves the
  task server per poll instead of pinning a port (#3445).

## Floor-raising

Two mypy backlogs cleared (core/security #3497; core/orchestration #3495,
which surfaced and fixed a real cron-trigger defect on the way), cast
aliases made into real types (#3493), coverage ratcheted to 83.25% in three
steps, every TypeScript package brought under the typecheck gate (#3413),
translated READMEs gated for sync (#3457), the secret-scanning gate pinned
to an exact scanner release instead of `latest` (#3535) and taught to stop
failing on ordinary test names (#3488), and the four structural guards main
was quietly failing restored and made path-aware (#3520, #3522).

Upgrade in place. The surviving folds print their new names; `postmortem`,
`incident`, `commit-stats`, `consensus` and `issue-to-pr` do not — they are
gone, mappings above. Beyond that, the things worth checking before you
upgrade: anything that parses plan files — plan loading got stricter,
deliberately (#3534, #3539), though the standalone `dry-run --plan` does not
yet propagate load failures (#3550) — and anything keying on verification exit
codes, which are aligned across the two verifiers for the downgrade cases
listed above (#3407); removed audit evidence still diverges (`trace
verify-projection` exit 0, `telemetry verify-span` exit 1 — #3551). Journal
parsing in the verify paths is unchanged — still lenient, tracked in #3549.
