# v3.24.1

A patch release on top of v3.24.0. It applies default per-client attempt
limits to authentication endpoints that were left on the generic request
rate alone since v1.4.10 (#6874). There are no breaking changes and no
configuration migration is required.

## Authentication attempt limits

Dashboard login, SSO login and callbacks, and CLI device authorization
endpoints now share a default limit of 10 attempts per client in
60 seconds, including their `/api/v1` aliases (#6874). Exhausted budgets
return HTTP 429 with `Retry-After` and an exponentially increasing
lockout. Failed dashboard credentials also trigger per-client backoff;
a successful login clears only that client's backoff. Existing seed
`rate_limit` buckets can override the attempt count and window.

The `/api/v1` aliases of these routes receive the same limits, using
the canonical-path resolution introduced in v3.24.0 (#6871).

## Upgrading

```bash
pipx upgrade bernstein     # or: uv tool upgrade bernstein
```

No configuration migration is required. Every capability available in
v3.24.0 is unchanged.
