# v3.24.0

This release adds cooperative task cancellation, a resumable journal stream for the terminal UI, and local merge-backs that can skip pushing to the remote (#6742, #6846, #5982). Graduation diagnostics can compare stored counters with sealed journal observations, and audit verification now checks published hash tiles (#6859, #6548).

## Stop work before releasing its claim

Operators can request a cooperative stop with `POST /tasks/{id}/cancel?stop_mode=request`; claimed or running work enters `stop_req` and retains its claim until the orchestrator observes termination (#6742). The orchestrator sends shutdown intent, then escalates verified independent local process groups through INT, TERM and bounded KILL attempts; observed termination leads to cancellation and one claim-release receipt (#6742).

Immediate cancellation remains the default, and a server without a running orchestrator leaves cooperative requests pending (#6742). A live in-process thread keeps its claim even if it ignores shutdown, and the reaper's execution registry is held in memory (#6742). Real POSIX process tests check escalation and release after observed death; Windows execution was not verified with real processes (#6742).

## Follow a run's journal in the terminal

`GET /events/thread?run=<run_id>` streams a selected run's journal with journal indices as SSE ids, and `Last-Event-ID` resumes after the last delivered index, including across server restarts (#6846). With `BERNSTEIN_TUI_STREAM=1`, the terminal UI follows the run selected by `BERNSTEIN_TUI_RUN` or the current run-owner record, and starts from index zero when the selected run changes (#6846). Resume depends on retained journal rows; pruning, damaged rows and reused run ids can leave gaps that `bernstein thread verify` reports (#6846).

The consumer buffers frames across network chunks and advances its cursor only after a complete frame; reconnect overlap is discarded, and an oversized frame switches the session to polling (#6842). A selected run without a journal uses snapshot polling until run selection changes or disappears and returns; an invalid server URL logs one configuration error and stops the consumer (#6851). Route-to-consumer tests exercise real journal rows, while decoder tests cover every single split point and seeded partitions of representative frames (#6846, #6842).

SSE slots remain occupied until their streams close, with release on completion, disconnect, cancellation or stream error (#6869). `/api/v1` aliases share the canonical route's request limits and SSE cap; canonical bucket rules take precedence while versioned-only configurations remain supported (#6871).

## Keep merge-backs local

Set `BERNSTEIN_LOCAL_ONLY=1` to merge completed work locally while skipping the push and its remote I/O (#5982). Pending-push retries are skipped too, and their queue stays intact so clearing the flag resumes them (#5982). The flag covers merge-back pushes only: salvage-branch pushes and evolution-mode pushes can still reach the remote (#5982). Regression tests check that the push function is never called and that the deferred queue remains byte-identical (#5982).

## Compare graduation counters with sealed observations

Graduation diagnostics can derive terminal-event counts and event-index ranges from a declared journal window, checking the complete snapshot against an independent seal before comparing it with stored counters (#6859). Damaged or truncated evidence is refused, and unknown events and unsupported metrics remain visible (#6859). Results explicitly report `stage_metrics_parity: not_established`; these event counts do not establish stage attribution, elapsed time or cost, and promotion decisions are unchanged (#6859). Tests exercise journal edits, complete-row truncation and torn or discarded rows (#6859).

## Verify the evidence that was written

`bernstein audit verify` now reports a Hash Tiles pillar, checking published tiles against authenticated segment bytes and naming damaged, truncated or unreadable tiles, including with `--hmac-only` and `--merkle-only` (#6548). Tiles beside damaged segments or without a matching segment are reported as not judged, and verification remains read-only (#6548). Reading the tile snapshot before segment data avoids a false failure when sealing overlaps verification; CLI tests cover damage, concurrent sealing and unchanged on-disk bytes (#6548).

Failed evolution rollbacks retain a checksum-protected receipt with the proposal, error and exact subset of files restored before failure; if receipt storage also fails, the error reports both failures (#6857). Missing or invalid backup records raise `RollbackError` while retaining the backup manifest, and success receipts keep their format (#6857).

Injected skills are written as the same UTF-8 bytes their audit digest covers, so Windows newline translation no longer makes the file disagree with its recorded digest (#6636). Regression tests check simulated Windows text writes and equivalence between LF and CRLF templates (#6636).
