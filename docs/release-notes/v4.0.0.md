# v4.0.0

## At a glance

- If a workflow node fails, Bernstein skips later layers, including independent branches, as in `bernstein workflow resume`. A detached SSH task with a nonzero remote exit fails the run and leaves later tasks pending.
- `bernstein govern audit --strict` gives CI distinct exit codes for failed checks and unmeasurable prerequisites.
- At run close, Bernstein seals the final delegation digest, hop count and manifest configuration with the install audit key.
- Fleet selection identifies an enabled instance where one worker matches the task type, dispatch tier and required capabilities.

[What is partial in 4.0.0](#what-is-partial-in-400) summarizes selected features and their limits.

## Before you upgrade

Read the [3.24 to 4.0 migration guide](https://github.com/sipyourdrink-ltd/bernstein/blob/v4.0.0/docs/operations/migration-3.24-to-4.0.md).

1. **Quality gates.** Previously ignored settings such as `quality_gates.large_file_check` in `bernstein.yaml` now apply. A value of the wrong type raises `SeedError` (#6615).
2. **Delegation verification.** If a manifest declares a final head with a missing or invalid seal, `bernstein delegation verify` exits `1`. This includes heads declared before seals existed. An otherwise intact, nonempty chain with no final declaration reports `valid=false` and exits `3`. An interrupted close can leave the declaration missing (#5352).
3. **MCP versions.** Bernstein uses SDK 2.3.x with the 2025-11-25 task wire contract. By default, the HTTP transport returns 400 for an unsupported `MCP-Protocol-Version` header. During the handshake, the server answers an unknown `initialize.params.protocolVersion` with its default revision.
4. **Quarantine.** The default workspace skill loader saves initialization failure reasons across restarts. A bare `SkillLoader` keeps them in memory. Persisting runtime plugin failures in quarantine requires a workspace store and `record_declaration_failures=True`.

After upgrading, run the audit from the project root and check which prerequisites it could measure.

```bash
bernstein govern audit --format json --strict
```

## Governance and audit

`bernstein govern audit` writes text, JSON or SARIF 2.1.0. Run it from the repository root for workspace-relative SARIF locations. `--quiet` suppresses the report.

| Result | Default | `--strict` |
| --- | --- | --- |
| Any check fails or crashes, or a measured finding has `passed=null` | 1 | 1 |
| Otherwise, at least one prerequisite is unmeasurable | 1 | 2 |
| A nonempty selection returns only passes, declarations or both | 0 | 0 |
| Empty selection | 1 | 1 |
| CLI usage error | 2 | 2 |

The full table is in [governance operations](https://github.com/sipyourdrink-ltd/bernstein/blob/v4.0.0/docs/operations/governance.md#govern-audit-machine-readable-output-and-ci-gates).

- **Compare reports.** Use `--since BASE_SHA256 --against HEAD_SHA256` together to compare two stored audit reports offline.
- **Policy-library checks.** `govern audit --only CMP` runs the checks reported in `compliance check` JSON.
- **ISO/IEC 42005 export.** `bernstein audit export --standard iso-42005` exports the evidence Bernstein holds for an AI impact assessment.
- **Control coverage.** `bernstein compliance controls` lists the benchmark suites that declare each control and their recorded measurements. Later submissions take precedence. The display says `unavailable` when no measurement exists.
- **Scorecard baselines.** An install-identity baseline stays neutral without a matching trusted key. Supply the public key with `bernstein bench run SUITE --baseline BASELINE.json --trusted-key FINGERPRINT=PATH`. Stub baselines require `--stub-signer` and successful replay.

## Evidence integrity and supply chain

- **Delegation seals.** Verification detects records removed, replaced or appended at the tail after close. It cannot detect replay of an authentic snapshot, an unrecorded action or changes made with the audit key. Older runs receive no backfill.
- **Hash profile.** `hash_profile: jcs-v2` in `bernstein.yaml` opts a new run's journal, lineage spine and receipt into RFC 8785 canonical JSON. Bernstein signs the receipt only with a signing key configured. `py-json-v1` remains the default.
- **Release provenance.** GitHub Releases include a Sigstore provenance bundle.
- **OSV-Scanner.** The adapter scans against a pinned local database and rejects digest mismatches and time-dependent rules (`ignoreUntil`, `effectiveUntil`). This covers part of #2958.
- **CoSAI evidence map.** The map includes MCP-T1 through MCP-T12 from the 2026-01-08 revision.
- **Custody signers.** Detached-JWS lineage signers can use an existing custody signer without exporting the private key.
- **Offline signing.** Offline wheelhouse signing keeps working with cosign 3.1.4.

## Fleet routing and resources

- **Dispatch tiers.** Generated tasks get a dispatch tier from their runtime requirements. Each batch runs tasks from one tier. Tiers survive REST requests, PostgreSQL storage, YAML plan loading and both retry paths.
- **Routing hints.** The `model`, `effort`, `cli` and `requires` hints survive a restart in the REST API and the JSONL TaskStore.
- **Worker heartbeats.** Disk, memory and mesh-latency readings can guide node selection, task stealing and worker pulls.
- **Live view.** `bernstein live` shows registered remote workers and the tasks they claimed.

## Execution correctness

- **Cost corrections.** The budget stop counts increases in explicit cumulative cost above spend already recorded, even when token counts stay flat. The current snapshot format omits the prior explicit cost. After restart, the first report for a restored entry can miss a cost increase if no tokens were added.
- **Orphaned tasks.** After a clean worker exit, an eligible non-artifact task with no new commits or worktree changes can complete if its declared completion signals already pass on the base commit.
- **Completion timeout.** `BERNSTEIN_SIGNAL_TIMEOUT_S` sets the timeout for a `test_passes` command. It defaults to 120 seconds.
- **Sandbox leases.** A holder can release only its own active lease. `bernstein doctor` reports owner task statuses for confirmed leaks older than the configured threshold (24 hours by default). It warns when a confirmed leak's age is unknown.
- **Reconcile helper.** It skips completed work, stops on failure and can resume a trusted partial run.
- **Required gates.** A failing or inconclusive plugin result blocks promotion when `GatePipelineStep.required` is true. An explicit block from the plugin also applies on an optional step.

## Models and adapters

- **OpenAI and Codex.** `provider=openai` uses the OpenAI API client. The Codex adapter validates and forwards reasoning effort before spawning.
- **Retries.** An explicit role or run model pin takes precedence. Otherwise, a retry keeps a supplied provider-prefixed model. With neither a known model nor a pin, the adapter resolves its default (#6605).
- **Pi.** Pi runs with `--print --mode json` and streams events to the runner log.
- **New adapter contracts.** The release adds CLI contracts for `cline`, `autohand`, `openhands`, `cody`, `composio` and `ralphex`. Adapters generated from the template match the current `CLIAdapter` contract.

## MCP and spawn policy

- **MCP tasks.** The persistent TaskStore backs task creation, polling, result retrieval, listing and cancellation on the 2025-11-25 wire contract.
- **Capability observations.** With `--observe-capabilities`, the gateway hashes each complete tool definition and each top-level field after the upstream handshake. The snapshot stores those digests. On a change, `mcp.capability_drift` records previous and current digests and the changed field names per tool. The repository includes [test vectors](https://github.com/sipyourdrink-ltd/bernstein/blob/v4.0.0/tests/fixtures/mcp_tool_definition_vectors.json).
- **Server manifest verification.** With signing checks enabled and an audit chain supplied, the MCP pre-load check records the server manifest's signature verdict, the bundle scan status and the load decision.
- **External policy registry.** For fresh direct-adapter spawns, an injected registry checks each attempt's adapter, model and endpoint, including failover. At least one policy hook must return `ALLOW`.
- **Role allow-lists.** Roles without a named policy can use a `*` adapter allow-list. An empty default denies every adapter.

## Dashboard, diagnostics and developer experience

- **Dashboard.** Task status shows tenant-scoped coordinator readiness. MCP status reports the coordinator and bridge versions separately.
- **Quarantine.** Workspace quarantine can also record reasons for malformed routine trigger declarations and invalid issue trackers.
- **Windows.** Artifact-mode completion handles agent IDs containing `:`. A directory at a declared output path reports "wrote no output".
- **Telemetry.** `bernstein telemetry verify-span` reads span JSON from standard input with `--span -` or `--span @-`.
- Snapshots work inside linked Git worktrees. Flaky-test detection retains pytest errors, and GitLab webhook events follow configured trigger rules.

## Documentation, CI and maintenance

- **Workflow docs.** The manifest reference distinguishes dispatch, verified completion and successful command execution. Resume examples supply the goal again because snapshots omit it.
- **CI.** Dependabot skips auto-merge on draft PRs. Maintainer review on protected automation changes excludes known writers. A maintainer PR follows ordinary review rules if a commit author is neither on the roster nor the built-in `github-actions[bot]` account.
- **Characterization tests.** Strict expected failures document known gaps in workflow execution and recovery (#6639).

## Known limitations

- With an injected policy registry, bridge, in-process, container, sandbox and crash-resume paths refuse before execution. CLI policy loading is still pending (#4912).
- The detached local path without an SSH sidecar records task lifecycle events but does not yet execute the submitted task.
- Regular fixes ship on 4.0.x. The only planned 3.24.x backport is 3.24.2.

## OSV-Scanner adapter, pinned to a local database

`get_scanner("osv-scanner")` returns a feed-pinned SCA adapter. It runs
`osv-scanner scan source --offline` against a local OSV database
(`OSV_SCANNER_LOCAL_DB_CACHE_DIRECTORY`), never against osv.dev, whose answer
changes as advisories are published. The caller pins the database in
`scope.config["db_pin"]`. The adapter digests every `osv-scanner/<ecosystem>/all.zip`
under the root and refuses to scan when the digest differs, as the Trivy
adapter does for `trivy.db`.

Finding identity includes the vulnerability id, normalized lockfile path,
severity, summary and affected package metadata. Windows drive and UNC file
URIs use the shared path normalizer so checkout locations do not change
in-scope finding hashes. Any `osv-scanner.toml` ignore list in the target tree
feeds the recorded invocation hash. Include/exclude globs and max-depth scope
limits are refused rather than ignored. Partial implementation of #2958.

SARIF reports that explicitly mark any invocation as unsuccessful are
rejected, including reports with no findings. Absent invocation metadata
and successful invocations preserve the existing finding normalization.

Config identity uses the versioned `osv-scanner-config-v2` digest of sorted
target-relative POSIX paths and exact file bytes: moving an ignore list between
package directories changes invocation identity, while moving the entire checkout
does not. Before any vendor process, the adapter parses TOML and rejects explicit
`IgnoredVulns.ignoreUntil` and `PackageOverrides.effectiveUntil` fields (including
case variants), because OSV-Scanner evaluates them against the current time.
Timeless configs and temporal words in comments or reasons remain supported;
unreadable or invalid TOML configs are refused rather than left unvalidated.

## Graph trace ingest adapter for graph-shaped agent runtimes

Ingests foreign execution traces from graph-shaped agent runtimes through the ingest adapter plugin boundary without modifying core scheduling logic (#4964).

The adapter retains foreign nodes, edges, input/output state and tool calls in its ingested representation, and maps node identities and edges to Bernstein's lineage task graph vocabulary (`RunPlan` / `PlanNode`). Every tool call carries a deterministic digest of its normalized arguments. Graph text renderings remain byte-identical across repeated ingests.

Input/output state must be mappings, edge conditions must be booleans, and node
identifiers and edge endpoints must be non-empty strings. Tool calls require a
non-empty name. Display fields reject control characters and line separators
before rendering. Missing roles remain unassigned. The lineage projection keeps
cycles and flattens conditional edges into dependencies; it describes recorded
structure and is not a schedulable execution plan.

This is the entry-point-registered ingest-boundary slice of #4964. String inputs
are JSON; local files require an explicit `Path`. Malformed tool-call entries are
rejected instead of silently discarded. The fixture is synthetic, and the
dependency-free callback recorder is tested with hand-driven events. Real-runtime
callback conformance and recorded-fixture provenance, production declaration
collection, CLI/replay wiring, and offline receipts remain follow-up work.

- Allow reusable lineage detached-JWS signers to use an existing custody signer without exporting private key material. Existing PEM callers and signature bytes remain compatible.

Expose all existing CMP policy-library observations through `govern audit
--only CMP` and include identical workspace findings in `compliance check`
JSON. Policy snapshots now use project observations unless explicitly
overridden by declaration flags. Framework profiles mark required check IDs
without changing verdicts or asserting conformance.

CMP execution errors retain their check area and use the shared registry's
exception isolation on both JSON surfaces. Under `govern audit --strict`, a
crashed CMP check returns exit 1 rather than the incompleteness exit 2.

The existing framework profile annotation is also retained in each SARIF
result's properties, without changing the check verdict or command exit code.

## Governance audit JSON, SARIF and CI exit codes

`bernstein govern audit` now supports `--format text|json|sarif`, `--strict`
and `--quiet`. JSON preserves the complete finding fields, including `id` and
`message` (also included in `doctor --json`). SARIF 2.1.0 includes check rules
and workspace-relative file locations; passing checks use `kind: pass` and
`level: none`. Unmeasurable results use `kind: review` and `level: none`, with
their reason in the message. Evidence locators are omitted, and absolute local
paths in diagnostics are redacted. Run from the repository root for code scanning.
`--quiet` suppresses reports and check-crash warnings while retaining sentinel
journaling and notifications.

The default gate keeps exit `1` for failures, check crashes and unmeasurable
checks. `--strict` distinguishes unmeasurable prerequisites with exit `2`,
unless a check failed or crashed (exit `1` takes precedence). Measured findings
without an explicit pass fail closed. Click usage errors, including incompatible
output flags, also exit `2`. Declared findings no longer fail the gate: they
previously caused exit `1` on main and now allow exit `0` when no other finding
blocks it. An empty selection exits `1`. See the complete exit-code table in
[governance operations](https://github.com/sipyourdrink-ltd/bernstein/blob/v4.0.0/docs/operations/governance.md#govern-audit-machine-readable-output-and-ci-gates).

Add a callback-based reconcile apply helper that records already-satisfied intents as skips, stops on failure, and resumes trusted same-context partial receipts without repeating successful changes. Retain stable intent keys and require separate policy authorization.

- Add one `hash_profile` selection in `bernstein.yaml` for a new run's journal, lineage spine and receipt (signed when a signing key is configured). `jcs-v2` opts into RFC 8785; unknown profiles fail closed.
- The first release containing this fragment is the declared compatibility release. `py-json-v1` remains the default for that whole release. Changing the new-run default to `jcs-v2` requires a separate later PR after measured soak; this release does not flip it.
- Existing evidence retains its recorded profile, or `py-json-v1` when absent, and reopens and verifies without rewriting historical bytes.

- Preserve declared verification scopes in plugin results and cached gate reports, and retain the reason for inconclusive plugin results. Legacy cache entries remain without coverage declarations.

## Delegation verification detects changes to a sealed final receipt chain

Run close atomically seals the final delegation digest, hop count and manifest
configuration with the install audit key. Every delegation verifier checks that
seal and the declared head/count: tail deletion, substitution and post-close
growth fail, even if a keyless writer recomputes the manifest checksum. Missing
declarations are incomplete (`valid=false`, exit `3`), including pre-upgrade runs
and interrupted finalization. Existing unsigned head declarations fail seal
verification; they are not silently upgraded from the remaining ledger (#5352).

Open and legacy runs retain their intact, authority-checked delegated ceilings
in the agent registry, marked by `incomplete_runs`; saved version-1 registry
snapshots remain verifiable. Access reviews exclude incomplete or mismatched
chains from verified sources. Incomplete chains never report a passing verdict.

This does not detect replay of an earlier authentic snapshot, prove that every
runtime action was recorded, or protect against a writer holding the audit key.
Deleting a declaration yields incomplete, never a completeness claim. There is
no automatic backfill: the remaining receipts cannot establish a historical tail.

## Compliance control-to-suite coverage and latest measurements

`bernstein compliance controls` now surfaces the declaring benchmark suites and
latest recorded measurement for each registry control across text, Markdown,
and JSON outputs (#5455, #7098):

- Built-in benchmark suite control declarations are exposed from a single shared
  mapping in `bernstein.eval.bench.bench_cli`, paired with tests verifying every
  registered built-in suite declares at least one valid registry control ID.
- `bernstein.compliance.control_coverage` joins the central control registry
  with built-in (and optional custom `.suite.json`) declarations and

- `bernstein compliance controls` accepts optional repeatable `--bundle` and
  `--bundle-dir` flags (falling back to `.sdd/bench` / `.sdd/benchmarks` when

## A failed workflow node now stops every later layer

`bernstein workflow run` (and `WorkflowRunner.run`) used to keep
dispatching nodes in later layers after a node failed, whenever those
nodes depended only on branches that had passed. Those nodes ran their
commands or agents, wrote `success` checkpoints, and appeared twice in the
result. A failure now skips every later layer once, without dispatching
anything, matching `bernstein workflow resume`.
